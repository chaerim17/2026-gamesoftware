# 게임 개발 지침

이 문서는 Codex가 이 프로젝트를 분석·설계·수정할 때 유지할 기본 방향이다. 사용자가 이후 명시적으로 변경한 요구사항이 있으면 최신 지시를 우선한다.

## 확정된 프로젝트 목표

- 실시간 렌더링 기반의 게임을 제작한다.
- 쿼터뷰 시점의 2.5D 오픈월드 RPG를 지향한다.
- 현재 기반은 C++ / OpenGL / GLEW / FreeGLUT를 사용하는 SimpleGame 프로젝트다.
- 렌더러 자체의 고도화보다 실제 게임 플레이에 필요한 기능을 기준으로 확장한다.
- 2D 스프라이트 기반인지 3D 공간과 고정 카메라 기반인지는 아직 확정하지 않았다. 쿼터뷰를 특정 투영 방식으로 임의 확정하지 않는다.

## 세계와 분위기의 기본 방향

- 고대 도시, 중세의 무장 전사, 검투사와 결투장 등의 소재를 선호한다.
- 정돈된 도시 정치나 명성 경쟁보다 거칠고 야생적인 모험을 강조한다.
- 검·활·창·방패 등 현실적인 무기를 중심으로 전투를 구성한다. 총기와 마법 중심의 전투는 기본 방향에서 제외한다.
- 황야, 숲, 협곡, 산맥, 폐허, 부족의 야영지와 같은 공간이 어울린다.
- 생존, 여정, 의리, 귀환, 사람을 지키기 위한 싸움을 주요 정서로 삼는다.
- 정확한 역사 시대와 초자연적 요소의 존재 여부는 미확정이다. 고대풍 가상 세계는 현재 유력한 초안이지 역사 설정의 확정은 아니다.

## 스토리와 목표 설계

- 사용자는 누군가를 구하거나 명확한 업적을 달성하는 등 목표 지향적인 이야기를 선호한다.
- 사용자가 언급한 '오디세이 같은 방향'을 참고하여 긴 여정과 시련, 분명한 목적지를 중심으로 구성한다. 특정 작품의 설정을 그대로 적용하지 않는다.
- 자유 탐험 중에도 플레이어가 무엇을 위해 이동하고 싸우는지 알 수 있어야 한다.
- 오픈월드는 목적을 흐리기보다 목적지에 도달하는 경로와 해결 방법을 선택하게 하는 방향으로 설계한다.
- 성장과 전투 보상은 사람의 구출, 길의 개방, 동료 확보, 목적지 접근 등 여정의 진전에 연결한다.
- 긴급한 구출 설정과 무제한 자유 탐험이 충돌하지 않도록 시간적 압박을 설계한다.

## 현재 스토리 초안 — 변경 가능

아래 내용은 대화에서 제안된 작업용 초안이다. 사용자가 세부 사항을 확정한 것으로 취급하지 않는다.

전쟁에서 돌아온 전사가 폐허가 된 고향을 발견하고, 사라진 부족과 가족의 흔적을 따라 거대한 야생을 횡단한다. 부족은 산맥 너머 옛 고향으로 향하고 있으며 정복군의 위협을 받고 있다.

이야기의 흐름은 '행방을 찾는다 → 부족을 따라잡는다 → 함께 목적지에 도달한다'이다. 재회 이후에는 주인공이 부족을 이끌고 마지막 길을 개척한다. 목적지의 임시 명칭은 '첫 불의 계곡'이다.

투기장은 명성 수집만을 위한 시설보다 포로의 자유, 통행권, 부족 내 도전권을 얻는 거친 결투 공간으로 활용할 수 있다. 핵심 동기는 '최강자가 된다'보다 '살아남아 내 사람들을 데려간다'에 둔다.

주인공의 신분, 구출 대상과의 관계, 부족과 적의 설정, 지명, 결말은 미확정이다. 이전에 제안된 도시별 명성 획득과 수도 투기장 중심 이야기는 현재 기본 줄거리로 채택하지 않는다.

## 구현 방향

- 입력 처리, 시간 기반 상태 갱신, 렌더링을 구분한다.
- 월드 좌표와 화면 좌표를 분리하고 쿼터뷰 투영 및 입력 좌표 변환을 고려한다.
- 바닥 위치와 높이, 객체의 앞뒤 가림 관계를 명확하게 관리한다.
- 작은 지역에서 이동·충돌·카메라 추적·NPC 상호작용이 가능한 플레이를 먼저 만든다.
- 이후 월드 구역 관리, 전투, 능력치, 인벤토리, 퀘스트, 저장 기능을 필요에 따라 확장한다.
- 대규모 오픈월드 시스템을 선제적으로 모두 구현하지 않는다. 현재 기능에 필요한 범위에서 확장 가능한 구조를 만든다.

## Codex 작업 원칙

- 특별한 상황이 아니면 빌드, 실행, 화면 및 플레이 결과 확인은 사용자가 직접 수행한다.
- Codex는 코드 분석·수정·정적 검토를 기본으로 수행하고, 필요한 수동 확인 항목을 안내한다.
- 예외적으로 직접 빌드나 실행 검증이 필요하면 그 이유를 먼저 설명한다. 수행하지 않은 검증을 통과했다고 보고하지 않는다.
- 확정된 요구사항, 제안, 미확정 사항을 구분한다. 아이디어 논의만으로 기능 구현이나 세부 설정 확정을 진행하지 않는다.
- 사용자가 요청한 범위를 중심으로 작업하고, 위 게임 방향과 충돌하는 변경은 명시적으로 설명한다.

## 튜토리얼 프로토타입 요구사항 (2026-09-09)

- 기존 마을 튜토리얼은 5분 이내 플레이를 목표로 한다. 이후 첫 사냥 레벨의 요구사항은 별도 절을 따른다.
- WASD 이동, 적절한 상호작용 키, 2.5D 쿼터뷰 표현이 필요하다.
- 작은 마을에서 시작하며, 주변 숲과 호수 및 다수의 마을 주민을 포함한다.
- 전체적인 야생적 분위기를 보여주는 렌더링과 게임의 목적에 맞는 작은 퀘스트를 제공한다.
- 현재 프로토타입은 절차적 도형으로 그리는 쿼터뷰 표현이다. 본편의 아트 제작 방식까지 확정한 것은 아니다.
- 상세 레벨 흐름, 조작법, 수동 확인 항목은 튜토리얼_레벨_설계.md를 참고한다.
- 실제 플레이 시간과 시각적 결과는 사용자의 빌드·실행 후 확인한다. 설계 목표와 검증 결과를 구분한다.

## 렌더링·월드 확장 요구사항 (프로토타입 0.2)

- 사용자가 첫 실행 결과를 확인한 뒤 렌더링 품질, 전체 한글화, NPC 두 배, 맵 네 배, 야생 짐승 추가를 요청했다.
- 기존 Renderer.cpp와 프로젝트 설정을 확장한다. 한글 글꼴·스프라이트 생성은 RendererAssets.cpp, 월드 표현·짐승은 TutorialWorld.cpp로 분리했다.
- 화면 후처리와 부드러운 지면 그림자, 세분화된 방향별 캐릭터 애니메이션, 흙·풀·석재·목재·초가지붕 재질, 물과 불 이펙트를 유지한다.
- 모든 게임 UI·대화·창 제목은 한글로 제공한다. 키 이름과 기술 식별자는 예외다.
- NPC는 9명에서 18명으로, 이동 가능한 맵은 가로·세로 각각 두 배(면적 네 배)로 확대했다.
- 사슴·멧돼지·늑대를 추가한다. 마을 튜토리얼에서는 배회·경계·회피·관찰 행동을 유지한다. 첫 사냥 레벨의 전투는 별도 구현한다.
- 확장 구역은 선택 탐험으로 두고 핵심 튜토리얼 동선의 5분 이내 목표를 유지한다.
- P는 후처리 비교 키다. 빌드, 실제 프레임률, 화면 품질과 플레이 시간 확인은 사용자가 수행한다.

## 코드 컨벤션 (2026-09-14)

- 저장소 루트의 .clang-format과 .editorconfig를 기준으로 작성한다.
- 공백 4칸을 사용하고, 함수·클래스·블록의 중괄호는 다음 줄에 배치한다.
- 짧은 함수와 조건문, 반복문도 한 줄에 압축하지 않는다. 여러 처리문을 세미콜론으로 이어 쓰지 않는다.
- 함수 사이에는 빈 줄을 넣고, 함수 내부에서도 초기화·검사·반복 처리·반환 등 의미가 바뀌는 지점을 빈 줄로 나눈다.
- 긴 인자 목록과 초기화 목록을 적절히 줄바꿈한다. 일반 코드는 한 줄 110자를 기준으로 하되 문자열 내용은 임의로 쪼개거나 변경하지 않는다.
- 기존 명명법과 include 순서를 유지한다. 서식 정리만 요청받은 경우 기능·데이터·문자열을 변경하지 않는다.
- Renderer.cpp 내부의 GLSL 원시 문자열도 읽기 쉽게 줄바꿈한다. GLSL 토큰과 전처리 지시문은 보존한다.
- 직접 관리하는 코드와 셰이더만 정리한다. Dependencies의 외부 라이브러리 코드는 일괄 포맷하지 않는다.
- 빌드·실행 대신 포맷 검사와 변경 전후 토큰 비교로 서식 변경을 검토한다.

## 첫 사냥 레벨 요구사항 (2026-09-14)

- 튜토리얼의 기본 플레이 환경 다음 단계로, 반복 사냥과 경험치 성장에 집중한 첫 레벨을 구성한다.
- 기본 실행은 첫 사냥 레벨이고, `--tutorial` 인자는 기존 마을 튜토리얼을 연다. 자동 레벨 전환은 아직 연결하지 않았다.
- 검 공격, 피격·사망·캠프 부활, 전리품 획득, 가방, 경험치 획득, 레벨 상승과 성장 포인트 배분을 제공한다.
- 레벨 3 달성·포인트 6개 배분·아이템 획득 후 캠프 귀환은 이번 구현의 초기 완료 조건이다. 본편 스토리 설정으로 확정하지 않는다.
- 맵은 무작위 생성하되 모든 이동 가능한 땅이 캠프와 연결되도록 보정한다. 물·나무·바위는 의도적인 장애물이다. 적과 전리품도 이동 가능한 곳에 둔다.
- 원·사각형·타원 등 기본 도형 기반의 모델을 유지한다. 생성한 모델과 캐릭터 애니메이션은 실행 파일 옆 GameData의 파일 캐시로 재사용한다. 캐시가 유효하면 다음 실행에서 재생성하지 않는다.
- 불꽃·연기·불티·물결 등 표현 가능한 효과는 셰이더로 처리한다. 모델 데이터와 캐릭터 아틀라스를 바꾸면 각 캐시 버전도 갱신한다.
- 경험치·배분 능력치·가방은 로컬 파일로 저장한다. 새 맵에서도 성장 정보는 유지한다.
- 상세 수치·조작·저장 범위·수동 확인 항목은 첫_레벨_설계.md를 참고한다.
- 앞으로 추가하는 코드도 기존 코드 컨벤션을 적용하며, 의미 단위 사이의 빈 줄을 적극적으로 사용한다.
