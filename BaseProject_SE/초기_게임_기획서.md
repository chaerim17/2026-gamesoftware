## 1. 게임 개요

**거친 고대·중세풍 세계를 검과 활로 헤쳐 나가며, 소중한 사람과 분명한 목적지를 향해 긴 여정을 완수하는 쿼터뷰 2.5D 오픈월드 RPG.**

위 문장은 현재 방향을 요약한 콘셉트 문장이다. 구출 대상과 목적지의 구체적인 설정은 변경할 수 있다.

## 2. 핵심 경험과 기획 원칙

### 2.1 목적이 있는 탐험

플레이어는 현재 찾는 대상, 향하는 장소, 길을 막는 문제를 이해할 수 있어야 한다. 탐험으로 얻은 단서·장비·관계는 여정의 진전에 연결한다. 지도상의 모든 활동을 완료해야만 이야기가 진행되는 구조는 기본안으로 삼지 않는다.

### 2.2 야생을 통과하는 전사

성벽 밖의 길, 낯선 부족, 맹수와 약탈자, 지형의 위험이 여정의 긴장감을 만든다. 야생적인 분위기는 과도한 잔혹함보다 스스로 길을 찾고 몸과 무기로 살아남는 경험으로 표현한다. 모닥불과 안전한 야영지는 위험한 외부와 대비되는 휴식 공간이다.

### 2.3 선택 가능한 길, 분명한 도착점

목적지는 공유하되 협곡 돌파, 우회 탐험, 결투, 인물의 도움 등 접근 방법에 선택을 둔다. 초기에는 적은 수의 실제로 다른 경로를 구현한다. 광대한 맵의 크기 자체보다 이동 중의 발견과 선택을 우선한다.

### 2.4 여정을 위한 성장

강해지는 이유는 더 위험한 길을 지나고 사람을 구하며 목적지에 도달하기 위해서다. 명성과 업적은 필요에 따라 통행이나 인물 관계의 수단으로 사용한다. 도시별 명성 획득과 수도 투기장 우승을 중심으로 한 이전 이야기는 현재 기본 줄거리가 아니다.

## 3. 시간적 배경과 세계관

**제안:** 철제 무기를 사용하는 고대 말기·중세 초기풍 가상 세계. 오래된 문명의 석조 도시와 도로가 남아 있고, 부족 사회와 정복 국가가 변경에서 충돌한다.

역사상의 특정 국가나 연대는 아직 정하지 않는다. 기사, 검투사, 부족 전사가 함께 등장한다면 각각의 사회적 역할과 장비 수준을 일관되게 정리한다.

| 공간 | 분위기와 플레이 역할 — 제안 |
|---|---|
| 황야·초원 | 먼 목적지를 바라보며 이동, 추격 흔적과 버려진 야영지 발견 |
| 원시림 | 시야 제한, 우회로 탐색, 사냥꾼이나 생존자와 만남 |
| 협곡·산길 | 좁은 길의 전투, 통행을 막는 집단과 대치 |
| 고대 폐허 | 사라진 문명의 흔적, 과거 이동 경로와 자원 발견 |
| 부족 야영지 | 휴식, 대화, 거래, 여정 정보 확보 |
| 석조 요새·거친 결투장 | 길을 장악한 세력, 포로의 자유나 통행권을 건 싸움 |

신앙·전설의 존재와 실제 초자연 현상의 존재는 별개의 미정 사항이다. 총기와 마법 중심 전투는 기본 개발 범위에 포함하지 않는다.

## 4. 시각·음향 방향

- 시각 소재: 흙먼지, 바위, 거친 천, 가죽, 닳은 철, 목책, 횃불.
- 색채 제안: 흙과 돌의 낮은 채도에 불빛, 깃발, 의복으로 지역과 인물의 차이를 준다. 화면 전체를 어둡게 만들어 식별성을 떨어뜨리지 않는다.
- 공간 구성: 지형의 높이와 폐허의 실루엣으로 방향감을 제공한다. 쿼터뷰에서 캐릭터와 공격 대상이 큰 전경 오브젝트에 가리지 않도록 한다.
- 음향 제안: 바람, 발걸음, 활시위, 금속 충돌, 짐승 소리, 야영지의 불과 대화. 전투와 안전 지역의 소리 차이로 긴장과 휴식을 표현한다.
- 아트 제작 방식: 픽셀 아트, 손그림, 저폴리 3D 등은 미정이다. 2.5D 요구만으로 특정 제작 방식을 확정하지 않는다.

## 5. 이야기 초안

### 5.1 도입

전쟁에 끌려갔던 전사가 수년 만에 고향으로 돌아온다. 마을은 폐허가 되었고 가족과 부족은 사라졌다. 남겨진 흔적을 통해 생존자들이 산맥 너머 조상들의 땅으로 이동했다는 사실을 알게 된다.

주인공은 부족의 흔적을 따라간다. 이동 경로에는 적대 세력과 위험한 지형이 있고, 부족의 뒤에는 정복군의 위협이 있다. 목적지의 임시 명칭은 '첫 불의 계곡'이다.

### 5.2 목표의 변화

| 단계 | 플레이어 목표 | 주요 활동 — 제안 |
|---|---|---|
| 1. 찾는다 | 생존 여부와 이동 경로 확인 | 폐허 조사, 생존자 대화, 흔적 추적 |
| 2. 따라잡는다 | 부족이 향한 길을 개척하고 재회 | 통행 문제 해결, 전투, 길잡이 구출, 경로 선택 |
| 3. 함께 도달한다 | 부족을 지킬 길과 정착지 확보 | 거점 확보, 위협 제거, 마지막 관문 돌파 |

재회 이후의 동행은 서사 방향이다. 대규모 NPC 호송·부족 시뮬레이션을 필수 기능으로 확정한 것은 아니다. 규모에 맞게 지역별 사건과 거점 상태 변화로 표현할 수 있다.

### 5.3 핵심 동기

'최강의 전사가 된다'보다 '살아남아 내 사람들을 데려간다'에 무게를 둔다. 개인적인 구출 동기와 여정 완수라는 성취를 함께 제공한다.

정확한 시한이 있는 구출과 자유 탐험이 충돌하지 않도록, 초기에는 행방을 추적하는 상황으로 긴장감을 만든다. 실제 시간 제한의 채택 여부는 미정이다.

### 5.4 미확정 설정

주인공의 이름·출신·성격, 구출 대상과의 관계, 부족의 문화, 적대 세력의 동기, 전쟁의 원인, 최종 목적지와 결말은 추가 결정이 필요하다. '오디세이'는 현재 긴 여정과 시련이라는 해석으로 사용하며, 특정 작품을 지칭한 것인지는 확인되지 않았다.

## 6. 플레이 구조

**단서 또는 목표 확인 → 경로 선택 → 탐험과 조우 → 전투 또는 상호작용 → 정보·장비·통행 가능성 획득 → 다음 목적지로 이동**

휴식과 정비는 이 흐름 사이에 배치한다. 부가 활동은 주된 여정과 다음 중 하나로 연결하는 것을 원칙으로 한다.

- 다음 지역의 단서나 우회로를 알아낸다.
- 길을 막는 적에 대응할 장비나 자원을 얻는다.
- 도움을 줄 인물 또는 안전한 거점을 확보한다.
- 지나온 지역과 부족의 사정을 이해한다.

단순한 반복 수집과 수치 보상만으로 월드의 대부분을 채우지 않는다.

## 7. 전투와 RPG 시스템

아래 세부 시스템은 요구사항을 구체화한 제안이며 구현 확정 목록은 아니다. 실시간 렌더링은 확정이지만 구체적인 전투 조작 방식은 추가 결정한다.

| 시스템 | 초기 제안 | 확장 후보 |
|---|---|---|
| 전투 | 검의 공격 거리·방향·타이밍, 피해와 사망 | 활, 방패, 회피, 적별 전술 |
| 적 | 접근 후 공격하는 기본 인간형 적 | 궁수, 맹수, 결투 상대 |
| 성장 | 여정 중 장비나 기본 능력의 향상 | 숙련도, 제한된 기술 선택 |
| 상호작용 | 대화, 조사, 목표 달성에 필요한 물건 획득 | 거래, 관계, 선택적 해결 |
| 퀘스트 | 단서 획득과 관문 개방이 연결된 짧은 목표 흐름 | 지역별 서사와 대안 경로 |
| 인벤토리 | 필요한 아이템의 소유 여부와 사용 | 장비 교체, 수량, 거래 |
| 저장 | 위치, 주요 상태, 완료한 목표의 보존 | 지역별 변화와 인물 상태 |

무기별 역할과 읽기 쉬운 공격 표현을 우선한다. 현실적인 무기를 선호한다는 요구를 복잡한 사실주의 시뮬레이션으로 확대 해석하지 않는다. 허기·갈증·내구도·제작·스태미나는 야생 분위기만을 이유로 의무적으로 추가하지 않는다.

## 8. 오픈월드와 화면 설계

최종 방향은 오픈월드지만 초기에는 작은 연결 지역을 만든다. 이후 실제 탐험 흐름에 맞춰 구역을 확장한다. 완전한 무로딩 월드, 절차적 생성, 전체 월드의 상시 시뮬레이션은 미확정이다.

쿼터뷰 화면에서 확인할 핵심 사항은 다음과 같다.

- 캐릭터의 발 위치와 실제 충돌 위치가 일치해야 한다.
- 지형·캐릭터·구조물의 가림 관계가 자연스러워야 한다.
- 화면 방향과 이동·공격 방향이 일관되어야 한다.
- 카메라가 이동 경로와 가까운 적을 읽기 쉽게 보여줘야 한다.
- UI에는 현재 목표와 필요한 전투 상태를 우선 표시한다.

미니맵, 목표 표식, 전체 지도, 조작 키, 마우스 이동 여부는 미정이다.

## 9. 첫 구현 범위

### 9.1 1차: 이동 가능한 작은 지역

쿼터뷰 표현, 플레이어 이동, 지형 충돌, 카메라 추적, NPC와의 기본 상호작용을 만든다. 임시 도형과 임시 리소스를 사용할 수 있다.

완료 기준: 사용자가 작은 지역을 이동하면서 장애물을 통과하지 않고, 카메라와 가림 표현을 확인하며 NPC의 안내를 받을 수 있다.

### 9.2 2차: 짧은 여정을 끝낼 수 있는 시제품

**제안 시나리오:** 폐허가 된 마을에서 출발해 야영 흔적을 찾고, 생존자의 안내를 받은 뒤, 통행을 막는 적을 상대하거나 우회하여 다음 지역으로 향하는 길을 연다.

포함 범위는 작은 지역 1개, 주요 무기인 검 1종, 기본 적 1종, 대화 가능한 인물 1명 이상, 연결된 짧은 목표 흐름, 기본 저장·불러오기다. 수량은 초기 범위를 억제하기 위한 제안이다.

완료 기준:

1. 처음 접한 사용자가 다음 목적과 이동 방향을 이해한다.
2. 탐험·상호작용·전투를 통해 시작부터 지역 목표 완료까지 진행할 수 있다.
3. 최소한 한 구간에서 서로 다른 경로를 선택할 수 있다.
4. 저장 후 주요 진행 상태가 복원된다.
5. 쿼터뷰의 가림과 이동 표현이 플레이를 방해하지 않는다.

### 9.3 후속 확장

활과 추가 적 유형, 장비 성장, 연결 지역, 지역 상태 저장을 순차 추가한다. 대규모 월드 스트리밍, 여러 부족의 관계, 긴 메인 스토리는 작은 지역의 플레이가 확인된 뒤 확장한다.

## 10. 기술적 개발 기준

2026-09-07 정적 분석 기준으로 현재 코드는 창 생성, 입력 콜백 등록, 셰이더와 정점 버퍼 생성, 단색 사각형 출력이 있는 기본 템플릿이다. 게임 기능은 앞으로 구현해야 하며 이 기획서 작성 과정에서 현재 빌드나 실행 상태를 재검증하지 않았다.

- 입력, 시간 기반 Update, Render의 책임을 분리한다.
- 게임 규칙과 충돌은 월드 좌표를 기준으로 하고 화면 표현 시 좌표를 변환한다.
- 높이와 가림 처리는 선택한 2.5D 제작 방식에 맞게 설계한다.
- 렌더러가 퀘스트·전투 규칙을 직접 소유하지 않도록 한다.
- 셰이더 초기화 실패 처리, 리소스 경로, 창 크기 변경, GPU 자원 해제는 초기 안정화 항목으로 관리한다.
- 월드 관리와 저장은 실제 초기 기능에서 필요한 상태부터 구현한다.
- 성능 목표는 목표 환경과 아트 방식 결정 후 수치화한다. 측정하지 않은 프레임률을 달성했다고 기재하지 않는다.

## 11. 개발 순서와 주요 위험

| 순서 | 작업 | 결정 또는 확인할 사항 |
|---|---|---|
| 1 | 표현 방식·조작 결정 | 스프라이트/3D, 투영, 이동·공격 입력 |
| 2 | 기본 루프와 렌더링 안정화 | 초기화 오류, 리소스 경로, 좌표 체계 |
| 3 | 작은 지역과 이동 | 카메라, 충돌, 가림 |
| 4 | 검 전투와 기본 적 | 공격 판정, 피해, 패배 후 흐름 |
| 5 | 짧은 여정 연결 | 대화, 조사, 목표 갱신, 경로 선택 |
| 6 | 기본 저장과 시제품 확인 | 진행 상태 복원, 처음부터 끝까지 플레이 |
| 7 | 확인 결과에 따라 확장 | 활, 성장, 지역 확대, 본편 이야기 |

일정은 개발 인원과 가용 시간이 정해진 후 산정한다. 가장 큰 범위 위험은 오픈월드의 콘텐츠 양이며, 가장 이른 기술 결정은 2.5D 제작 방식이다. 상세한 아트와 방대한 시스템을 먼저 만들기보다 작은 여정이 성립하는지 확인한다.

## 12. 향후 결정할 항목

우선 결정할 항목:

1. 2D 스프라이트 기반과 3D 공간 기반 중 어떤 방식으로 쿼터뷰를 구현할 것인가?
2. 이동·조준·공격 조작과 전투 속도는 어떻게 구성할 것인가?
3. 현재 부족 추적 이야기를 본편 줄거리로 채택할 것인가? 구출 대상은 누구인가?
4. 개발 인원·기간·사용할 수 있는 아트 리소스의 범위는 무엇인가?

이후 결정할 항목: 정확한 시대와 지리, 아트 스타일, 성장·장비 체계, 초자연적 요소의 범위, 월드 연결 방식, 저장 정책, 최종 플랫폼과 싱글/멀티 범위.

## 13. 협업과 문서 유지

- Codex는 이 기획서와 AGENTS.md를 바탕으로 분석·설계·수정한다. 사용자의 최신 명시적 지시를 우선한다.
- 특별한 상황이 아니면 빌드·실행·화면 및 플레이 결과 확인은 사용자가 직접 수행한다.
- Codex는 정적 검토와 필요한 수동 확인 항목을 제공한다. 직접 실행 검증이 필요한 예외 상황에는 이유를 먼저 설명한다.
- 새로운 제안을 확정 사항으로 바꾸거나 큰 범위의 시스템을 추가할 때는 사용자의 결정이 근거가 되어야 한다.
- 구현 현황과 기획 목표를 구분하고, 변경 시 버전과 결정 상태를 갱신한다.
